# Browser Playground frontend dependency intake

**Review date:** October 26, 2026
**Scope:** Stage 0 host and Stage 1 discovery client for issue #109.

## Introduced tooling

| Dependency                        | Pin     | Source and need                                                                                                         | Impact and controls                                                                                                                                                                                                |
| :-------------------------------- | :------ | :---------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node.js                           | 26.7.0  | Local runtime pin in `playground/.node-version`; npm scripts build and check the static client.                         | Developer/build-time only. Match the exact runtime before installing dependencies.                                                                                                                                 |
| npm                               | 12.2.0  | `packageManager` pin; produces and consumes `package-lock.json`.                                                        | Registry downloads are lockfile-pinned. `npm ci --ignore-scripts` was used for the clean install; package lifecycle scripts were not run.                                                                          |
| TypeScript                        | 6.0.3   | Exact dev dependency; static type checking for the worker protocol and client.                                          | Developer/build-time only. Resolved from npm and retained in `playground/package-lock.json`.                                                                                                                       |
| Vite                              | 7.3.7   | Exact dev dependency; production client bundling with configurable base paths.                                          | Developer/build-time only. The initial 7.1.12 pin surfaced high-severity advisories and was replaced with the fixed 7.3.7 release. Clean install and `npm audit --audit-level=high` returned zero vulnerabilities. |
| .NET WebAssembly SDK/runtime pack | 10.0.13 | NuGet.org package lock generated by the browser host project; required to publish .NET into browser WebAssembly assets. | Runtime browser assets are static application downloads, not a project package for consumers. NuGet restore uses repository locked-mode and audit settings.                                                        |

Vite's official release guidance identifies 7.3.7 as a supported patched 7.x
release; its package metadata requires Node `^20.19.0 || >=22.12.0`, compatible
with the repository's pinned Node 26.7.0. TypeScript 6.0.3 and Vite 7.3.7
installed cleanly and passed the repository's current client typecheck.

## Stage 1 runtime dependencies

| Candidate            | Metadata observed                  | Intake decision                                                                                                                                                                                                                                                                                                        |
| :------------------- | :--------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `monaco-editor`      | 0.57.0, MIT, Microsoft npm package | Approved for the accepted familiar editing experience. A textarea would not supply models, lexical colors, or diagnostic markers; another UI framework is unnecessary. Import the editor API and C# grammar only; bundle its editor worker locally. Transitive dependencies are `marked` 14.0.0 and DOMPurify.         |
| `fflate`             | 0.8.3, MIT, upstream npm package   | Approved for ZIP output. No runtime dependencies. Native compression streams do not create ZIP directory records; a maintained ZIP implementation avoids introducing a bespoke archive format writer. Stored entries (`level: 0`) avoid synchronous compression work for up to the adapter's 16 MiB output cap.        |
| `dompurify` override | 3.4.17, Apache-2.0 OR MPL-2.0      | Monaco 0.57.0 pins vulnerable 3.4.15. Initial install audit identified a critical advisory; override to the patched 3.4.17 release. Final `npm audit --audit-level=low` reports zero vulnerabilities. Retain and review this override when Monaco updates; do not remove it while the upstream pin remains vulnerable. |

## Quality and coverage tooling

| Dependency                                                         | Pin                     | Role and impact                                                                                                                      |
| :----------------------------------------------------------------- | :---------------------- | :----------------------------------------------------------------------------------------------------------------------------------- |
| ESLint, `@eslint/js`, `typescript-eslint`                          | 10.13.0, 10.0.1, 8.72.0 | Strict TypeScript linting; developer-only checks.                                                                                    |
| Prettier                                                           | 3.9.10                  | Consistent formatting for TypeScript, scripts, and configuration; developer-only.                                                    |
| c8                                                                 | 12.0.0                  | Node V8 coverage with 95% branch, 98% line, and 80% function gates for protocol/workspace utilities.                                 |
| Playwright                                                         | 1.64.1                  | Runs production-browser coverage in pinned Chromium. CI installs only Chromium's headless shell, avoiding the full browser download. |
| `fake-indexeddb`                                                   | 6.2.6                   | Exercises persistence behavior with Node's built-in test runner; not shipped to visitors.                                            |
| `istanbul-lib-coverage`, `istanbul-lib-report`, `istanbul-reports` | 3.2.2, 3.0.1, 3.2.0     | Merges Node and source-mapped browser coverage and emits Cobertura for Coveralls.                                                    |
| `v8-to-istanbul`                                                   | 9.3.0                   | Maps Chromium V8 coverage back to first-party TypeScript sources through Vite source maps.                                           |

All quality packages are exact-pinned dev dependencies in the npm lockfile.
The browser coverage run is restricted to `playground/src`, excluding bundled
Monaco and other third-party sources from the project metric. The repository
quality workflow uploads the browser Cobertura report together with the C#
adapter, compiler, and generator reports.

These packages resolve from the same approved npm registry as the build tools,
with exact direct pins and lockfile integrity hashes. No install lifecycle
scripts ran (`--ignore-scripts`); upstream development/build/prepack scripts
were inspected and are not invoked by application installation. DOMPurify's
runtime dependency on trusted-types declarations is retained in the lockfile.
The Vite build emits upstream licenses and Monaco's notices as
`third-party-notices.txt`. All editor, compiler, and archive assets are local;
no CDN or service receives workspace source. Review upstream releases and run
audit, type checks, production builds, and browser smoke checks on updates.
Monaco adds about 720 kB gzip to the editor entry plus its worker; include
public-network startup and browser compatibility in #110 qualification.

No React/UI framework, test runner package, or third-party MD5 package was
introduced. The maintained synchronous MD5 module reuses the implementation
and retained provider tests from commit `f995a3f3` in the accepted spike.

## Commands and evidence

- `npm install --package-lock-only --ignore-scripts --no-fund`
- `npm ci --ignore-scripts --no-fund`
- `npm audit --audit-level=high` — zero vulnerabilities after the Vite update.
- `npm run typecheck` — passed with TypeScript 6.0.3.
- `npm test` — 36 Node tests passed: the 21 retained MD5 provider checks, eight
  worker-state cases, and seven workspace/recovery cases.
- `npm run lint` and `npm run format:check` — passed.
- `npm run coverage` — passed with 98.78% branch, 99.17% line, and 81.25%
  function coverage for the covered Node modules.
- `npm run build:coverage` and `npm run coverage:browser` — all seven examples
  on both profiles and the editor/recovery flows passed in headless Chromium;
  the combined first-party report measured 93.47% branches and 92.88% lines.
- The C# adapter's 28 focused cases passed with 96.875% branch and 98.2% line
  coverage. The repository quality workflow includes its Cobertura report in
  the same Coveralls upload as compiler, generator, and browser coverage.
- `dotnet restore src/Wireloom.Playground.Browser/Wireloom.Playground.Browser.csproj --use-lock-file --locked-mode`
  — passed with NuGet audit enabled after registry access was available.

Browser verification used the official `@playwright/cli` package pinned to
0.1.22 through `npx`, with the installed Microsoft Edge browser. This is a
verification tool, with no application dependency or package manifest change.
The published worker passed parity, recovery, responsiveness, and limit checks
at root and nested paths. Results and measurement limits are recorded in the
[stage 0 evidence](../../plans/109-browser-playground-stage0-evidence.md).
