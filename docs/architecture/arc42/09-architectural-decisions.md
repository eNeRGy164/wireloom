# 9. Architectural decisions

The following decisions are reflected in the current implementation and its
tests. A separate ADR should be added when a decision needs a full options and
trade-offs record.

Union metadata adapts to RTI's signed discriminator representation where needed
to preserve IDL branch values. Signed 8-bit character labels match the RTI C++
oracle compiled with a single-byte execution charset; full-width unsigned
labels use signed 32-bit metadata storage. Managed discriminators retain their
declared ranges. Serializer payload checks validate these adaptations instead
of accepting data loss reproduced by an RTI-generated C# binding.

| Decision                                                       | Rationale                                                                                                                                                                            | Status / source                                                            |
| :------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------- |
| Use a managed Roslyn incremental generator                     | Keeps generation inside the .NET compiler and consumer build                                                                                                                         | Current; `src/Wireloom.Dds.Generator/Api/Generator.cs`                     |
| Keep the compiler core independent of Roslyn                   | Makes parsing, semantic validation, and emission easier to test and reason about                                                                                                     | Current; `IdlCompiler` and `FrontEnd`                                      |
| Make `DdsIdl` roots explicit                                   | Avoids accidental generation of every IDL file and gives each root clear metadata                                                                                                    | Current; package targets and integration tests                             |
| Require an explicit compatible RTI runtime reference           | Generated support is coupled to the application-selected RTI API surface                                                                                                             | Current; diagnostic `DDSG0003`                                             |
| Advance compatibility through small oracle-backed cases        | Prevents broad claims from a single successful compilation                                                                                                                           | Current; `docs/corpus` and compliance tests                                |
| Use RTI C# as a baseline and allow evidenced improvements      | Characterize existing behavior; allow deliberate managed API improvements supported by RTI C++ evidence, with separate wire verification                                             | Current; corpus oracles and chapter 8.6                                    |
| Preserve aliases in optional aggregate DynamicType members     | Mirrors RTI metadata while keeping managed member APIs and native conversions on the underlying aggregate type                                                                       | Current; C115 oracle and corpus compliance test                            |
| Treat root metadata as project-wide batch configuration        | The current compiler combines defines, undefines, include directories, and strictness across generating roots                                                                        | Current; `IdlCompilation`                                                  |
| Separate compiler orchestration, resolution, and emission      | Keeps the feature-complete pipeline independently testable and allows front-end, planning, and writer changes to remain local                                                        | Current; chapters 4–6 and `src/Wireloom.Dds.Generator/Compiler`            |
| Use explicit parse, bind, and validate phases                  | Keeps syntax capture, reference resolution, and complete-graph semantic checks distinct while preserving source-located diagnostics                                                  | Current; chapter 5 and `IdlCompilation`                                    |
| Bound preprocessing work and output                            | Trades acceptance of effectively unbounded inputs for deterministic build safety; limit failures reject the complete input rather than exposing partial text                         | Accepted; chapters 5, 6, 8, 10, and 11                                     |
| Keep wire compatibility as manually triggered evidence         | Allows licensed RTI C++ tooling and multi-version DDS exchanges without making proprietary toolchains a pull-request dependency                                                      | Current; chapter 6.3 and the wire-compatibility workflow                   |
| Use exact RTI 7.7.0 for the wire matrix                        | Keeps the licensed toolchain and runtime package fixed for wire evidence; the package reference floor does not establish compatibility with other releases                           | Current; chapter 6.3; RTI 7.3.1 generated-code compatibility is unverified |
| Include warning-only Wireloom-positive cases in wire selection | A warning does not make a generated case ineligible; wire results must still state limitations in generated shape fidelity; RTI-positive cases that Wireloom rejects remain excluded | Current; chapter 6.3; `05-array-of-sequences` remains marked with DDSG0105 |
