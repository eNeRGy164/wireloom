## Prepared release notes

Title: **v0.5.0 - A Wider Weave**

Wireloom 0.5.0 expands RTI LTS and .NET consumer support, adds more IDL language
features and configuration, and improves generated-code correctness and
compatibility evidence.

### Highlights

- Added generated API profiles for RTI Connext 7.3.1 and 7.7.0, selected from
  the consumer's resolved runtime reference. Continuous verification covers
  both LTS packages on Windows and Linux.
- Added .NET 8 consumer support with C# 12, including a fresh-package check in
  a .NET 8 SDK-only environment. Repository development still uses .NET 10.
- Expanded IDL support for grouped declarators, typed annotation defaults,
  enum constants, expression bounds, and explicit member-ID expressions.
  Fixed effective member-ID assignment across inheritance and automatic-ID
  policies.
- Added layered strict validation, configurable finite limits for unbounded
  strings and sequences, optional leading-underscore escaping, and a choice
  between RTI C# and IDL mappings for direct arrays of sequences.
- Added direct self-recursive sequence support and focused Wireloom C# and
  RTI C++ wire fixtures on both LTS versions. Improved collection alias member
  mapping, enum-array defaults, union initialization, and generated C# quality.
- Moved parsing, binding, validation, and emission into a compiler core bundled
  with the analyzer. Fixed project-reference analyzer dependency loading.
- Expanded retained RTI references, runtime contracts, packed-consumer checks,
  and wire reports. Added a checked-in Hello World sample and more configuration,
  migration, and release-evidence guidance.

### Upgrade notes

Regenerate contracts and review generated APIs when upgrading from 0.4.0,
especially when changing the RTI runtime version. The resolved RTI reference
now selects the generated API profile: versions from 7.3.1 up to 7.7.0 select
the 7.3.1 profile; 7.7.0 and later select the 7.7.0 profile. Only the two exact
LTS versions are qualification targets.

Naming violations can now report `DDSG0108` while still generating code in the
default permissive mode. Projects using warnings-as-errors may need to correct
the names or explicitly exempt that diagnostic. Enabling `Strict` turns those
violations into errors and prevents output for the batch.

The default direct sequence-array mapping remains `RtiCSharp`. Opting into
`Idl` changes the generated collection shape. Enabling `DdsIdlEnableEscapeChar`
removes one leading underscore from identifiers and can change generated names
and implicit hash member IDs. Review these settings before enabling them on
existing contracts. Unbounded sequence and string limits remain 100 and 255
unless configured; explicit IDL bounds take precedence.

### Compatibility scope

Support and evidence remain specific to IDL shapes and exact RTI toolchains.
Direct self-recursive sequence wire fixtures require the documented TypeObject
v1 settings and peer adjustments. Recursive sequence typedefs remain rejected;
mutually recursive struct graphs and recursive array TypeCode initialization
remain unqualified. RTI runtime limitations and peer workarounds remain visible
in the [support guide](../guides/support-and-compatibility.md) and
[feature coverage index](../corpus/FEATURE-COVERAGE.md).

The compiler assembly is included in the generator package; it is not a
separate NuGet package or consumer application reference. The generator still
requires an explicit `Rti.ConnextDds` runtime reference.
