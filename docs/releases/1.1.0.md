## Release notes

Wireloom 1.1.0 adds a native Modern C++ generator alongside the C# source
generator, introduces the RTI 6.1.2 C# profile, and expands the browser
Playground to preview both languages.

### Highlights

- **Modern C++ generation:** The new `Wireloom.Dds.Cpp.Generator` package
  bundles Windows x64 and Linux x64 native executables, CMake integration,
  and native Visual Studio/MSBuild integration. Generation needs no installed
  .NET runtime or RTI SDK. Building and running generated applications requires
  the selected RTI native SDK, toolchain, and applicable license. Released
  capabilities depend on the qualification matrix below.
  Native MSBuild tracks transitive includes and successful completion, so
  nonsemantic edits settle after one invocation and missing outputs regenerate.
- **RTI 6.1.2 for C#:** References from 6.1.2 through versions below 7.3.1
  select the new legacy profile. Existing 7.3.1 and 7.7.0 profile thresholds
  remain unchanged. Exact 6.1.2 corpus, runtime, packed-consumer, and wire
  checks join the verification matrix.
- **Modern C++ in the Playground:** The Playground introduced in 1.0.0 now
  supports Modern C++ generation, documentation previews, and CMake project
  export alongside its existing C# workflow. Compilation stays in the browser;
  application compilation and DDS qualification require their own checks.
- **Compatibility and validation:** Shared IDL preprocessing and parsing feed
  separate language backends. The wire harness includes scoped Wireloom C++
  peers and corrected unbounded exchanges. Retained corpus exports, C++ unit
  and fuzzing suites, native package checks, coverage, and mutation testing
  expand the available maintainer evidence.

### Upgrade from 1.0.0

1. After publication, update `Wireloom.Dds.Generator` to `1.1.0` and rebuild
   the projects that own IDL. Review regenerated contracts and handwritten
   partial extensions. Keep the RTI reference unchanged while validating the
   generator upgrade; changing it can select another API profile.
2. When adopting RTI 6.1.2, review its
   [profile restrictions](../guides/support-and-compatibility.md#rti-version-qualification).
   Its C# `int8` mapping uses `byte`, with signed behavior unsupported. Negative
   enum defaults in RTI reference aggregates and XCDR2 union-valued keys have
   additional limits. A mapped version range does not qualify every SDK in it.
3. Keep existing finite bounds, sequence-array mapping, and opt-in unbounded
   settings unless intentionally changing the data contract. The
   [1.x C# compatibility contract](../guides/support-and-compatibility.md#compatibility-and-stability)
   continues to apply.
4. Adopt C++ through its separate package and
   [package-based walkthrough](../guides/hello-world.md#modern-c-walkthrough).
   Pin the generator version and RTI profile independently. C++ public fields
   differ from RTI-generated accessor APIs; consult the
   [value-semantics guide](../guides/cpp-generated-value-semantics.md).
5. Retain the previous package, generated contracts, and build configuration
   until application and peer checks pass. For C#, restore the previous pin
   and rebuild. For C++, follow the documented
   [upgrade and rollback procedure](../../src/Wireloom.Dds.Cpp.Generator/README.md#update-and-roll-back).

## Known limits and evidence retention

- C++ generation is broader than its consumer, lifecycle, CDR, and live DDS
  qualification. Preserve per-shape evidence levels; a successful workflow or
  same-plugin loopback does not establish independent-peer compatibility.
- C114 has recorded Linux wide-string failures. C047 FlatData evidence is
  limited to RTI 7.7.0 and the final, unkeyed, fixed-size two-`long`,
  XCDR2-only shape. Recheck the
  [native qualification risks](../architecture/arc42/11-risks-and-technical-debt.md#116-modern-c-qualification-risks)
  against the release-source reports before advertising either capability.
- The [RTI distribution and maintenance policy](../guides/support-and-compatibility.md#rti-distribution-and-internal-interfaces)
  was clarified. Wireloom distributes
  no RTI packages or runtimes; consumers obtain RTI libraries and licenses.
  RTI does not support the internal-interface integration. Wireloom maintains
  its calls and updates them when supporting newer SDK versions. Exact-SDK
  ABI and native qualification checks remain required.
- Preparation wire results passed for all three profiles; final-source archive
  retention remains pending. Preserve original
  sanitized combined archives, readable reports, run/artifact IDs, source SHA,
  file sizes, and verified SHA-256 digests under the version's permanent
  archive. Link that archive here after qualification; retain failures too.
- Preview/native consumer artifacts expire after 14 days; release publishing
  artifacts expire after 90 days. Archive required evidence before expiry.
