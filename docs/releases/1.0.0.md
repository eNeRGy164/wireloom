## Release notes

Wireloom 1.0.0 defines the 1.x compatibility contract, adds opt-in support for
unbounded DDS collections and strings, and introduces a browser Playground
for exploring IDL and its generated C#.

### Highlights

- Added RTI-style unbounded sequences, narrow strings, and wide strings.
  Projects can enable the mode globally or override it on the file declaring
  a type. The finite fallback remains the default, and explicit IDL bounds
  continue to apply.
- Added a browser Playground for compiling multi-file IDL workspaces,
  inspecting generated C# and diagnostics, and exporting source archives.
  IDL is compiled in the browser and stays on the device.
- Defined what 1.x preserves for supported generated APIs, build integration,
  configuration defaults, and supported toolchains. The policy also describes
  corrections that can change faulty generated output.
- Expanded retained RTI references and wire fixtures for unbounded payloads,
  including loan return, repeated receives, and fragmentation. Check the
  release qualification record for the results on the tagged source.

### Upgrade from 0.5.0

1. Update the generator package and rebuild the projects that own the IDL.
   Review regenerated C# alongside handwritten partial extensions, then
   rebuild consumers. Keep the current RTI reference during the generator
   upgrade if you want to isolate generated-code differences. Changing that
   reference can select a different API profile.
2. Keep finite fallbacks when existing peers expect the current bounds.
   To adopt unbounded semantics, set `DdsIdlUnboundedSupport` in the project or
   `UnboundedSupport` on the item for the declaring file. A setting on an
   including file does not override the included file's declarations.
3. Review the values sent and received when opting in. Unbounded sequences can
   carry more elements, and strings can exceed the finite fallback length.
   Update peer generation options and check type discovery, payloads, and
   endpoint QoS on the exact RTI versions you deploy. Existing IDL bounds,
   sequence-array mapping, and strict-validation settings still apply.
4. Use the documented peer adjustments for direct self-recursive sequences.
   Recursive sequence typedefs remain unsupported and mutually recursive
   graphs remain outside the qualified scope.

See the [configuration guide](../guides/configuration.md#fixed-behavior-and-configurable-limits),
[migration guide](../migration/rtiddsgen-to-wireloom.md), and
[1.x compatibility contract](../guides/support-and-compatibility.md#compatibility-and-stability).

### Compatibility scope

Wire compatibility depends on the IDL shape, peers, RTI versions, and QoS
used in the exchange. Review the
[support boundary](../guides/support-and-compatibility.md#rti-version-qualification)
and [documented fixture adjustments](../testing/wire-fixtures.md) before
enabling unbounded behavior on an existing DDS topic.

## Wire evidence and limitations

The [licensed wire run](https://github.com/eNeRGy164/wireloom/actions/runs/41679384154)
completed both exact RTI profiles on the tag source. The
[retained wire evidence](../testing/wire-compatibility/evidence/1.0.0/README.md)
includes the original archives, readable reports, and verified hashes.

| RTI version | Exchanges | Passed | Failed | Not run |
| --- | ---: | ---: | ---: | ---: |
| 7.3.1 | 1,614 | 1,519 | 95 | 0 |
| 7.7.0 | 1,609 | 1,604 | 5 | 0 |

On RTI 7.3.1, 72 failures were in the unbounded alias, unbounded sample,
and nonfragmented receive-lifecycle fixtures. The reports show RTI writer
allocation failures among those exchanges. Both profiles passed the
fragmented receive-lifecycle fixtures under their configured QoS.

Both profiles recorded four failures in the default sequence-array mapping
and failures in the direct-recursion fixture. RTI 7.3.1 also recorded eight
minimum `int8` union failures, four enum-array default failures, and five
enum-constant fixture failures. The 7.3.1 profile excludes the inapplicable
`must_understand` case. Use the retained reports for individual pairings
and peer adjustments.
