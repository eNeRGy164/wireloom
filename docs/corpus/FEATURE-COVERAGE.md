# Corpus feature coverage

This is the feature index for the managed-generator compatibility corpus. Each case has a stable `C###` tag that can be used in test names, issues, and implementation work. Tags normally follow manifest order; explicit manifest tags preserve existing references when classified cases are added to an earlier group.

The status snapshot below was re-verified by the corpus compliance run on
2026-10-03. The run passed 230 case checks; the export-only test remains skipped
unless `CORPUS_GENERATOR_EXPORT_ROOT` is configured. This is source-generation
coverage only; runtime, serialization, wire, and live DDS behavior are excluded.

## Status meanings

- `implemented`: the managed generator compiles the IDL and the generated public data-contract shape contains the required RTI oracle types, properties, and enum members.
- `partial`: the managed generator compiles the IDL, but the public shape still differs from the oracle.
- `unsupported`: the RTI-positive case is currently rejected by the managed generator.
- `rejected`: a negative probe is rejected as expected by the managed generator.
- `mismatch`: a negative probe is accepted unexpectedly.
- `isolated`: the probe is present but must be run in an isolated process because the current compiler overflows in-process.
- `accepted`: the managed generator accepts the case, but no generated evidence is committed.
- `pending`: the case is reserved for an RTI probe; managed output is generated, but no RTI oracle is claimed yet.
- `environment-dependent`: observed RTI results differ across RTI/preprocessor environments; see the case diagnostics in the manifest.

RTI oracle links point to the licensee-generated C# source under `corpus/oracles`. Rejected RTI cases have no generated C# source. Each case source/plugin pair was compiled once against `Rti.ConnextDds` 7.7.0. The shared include pair ([source](oracles/includes/common.cs), [plugin](oracles/includes/commonPlugin.cs)), generated with RTI 7.7.0.1 / `rtiddsgen` 4.7.0.1, was compiled once into a reference assembly; both include-dependent pairs compiled against it. Of 72 case pairs, 68 compile as captured; four have C# compiler errors.

## PR #25 coverage crosswalk

PR #25 proposes seven feature follow-ups. RTI outcomes and diagnostics from
RTI 7.7.0.1 / `rtiddsgen` 4.7.0.1 are recorded in `manifest.json`; each case
below identifies the probe so later investigations can reuse the result.

| Feature | Corpus case | RTI result and follow-up |
| --- | --- | --- |
| Optional aggregate members | `C115` / [`09-optional-aggregate-member`](idl/features/09-optional-aggregate-member.idl) | **Accepted by RTI.** Wireloom rejects it; this is the clear RTI-parity follow-up. RTI source and plugin are linked in the positive cases table. |
| Direct sequence-of-sequences | `C058` / [`05-direct-sequence-of-sequences`](idl/negative/05-direct-sequence-of-sequences.idl) | **Rejected by RTI**; diagnostic is in the manifest. Nested collections through typedefs are accepted in `C017` / `05-shapes`. No RTI-parity follow-up for the direct form. |
| Forward aggregate declarations | `C081` / [`02-forward-declarations`](idl/features/02-forward-declarations.idl) | **Rejected by RTI** with an incomplete-type diagnostic. No RTI-parity follow-up. |
| 64-bit union discriminators | `C082` / [`07-union-long-long`](idl/features/07-union-long-long.idl); `C100` / [`12-union-64bit-label`](idl/negative/12-union-64bit-label.idl) | **Rejected by RTI** because `long long` is not a valid discriminator. A wide label is not independently tested because RTI rejects the discriminator first. No RTI-parity follow-up. |
| `map` | `C062` / [`12-unsupported-map`](idl/negative/12-unsupported-map.idl) | **Rejected by RTI** in the valid struct-member form `map<string, long> values`; parser diagnostic is in the manifest. No RTI-parity follow-up. |
| `bitset` | `C094` / [`12-bitset`](idl/negative/12-bitset.idl) | **Rejected by RTI**; parser diagnostic is in the manifest. No RTI-parity follow-up. |
| `bitmask` | `C093` / [`12-bitmask`](idl/negative/12-bitmask.idl) | **Rejected by RTI**; parser diagnostic is in the manifest. No RTI-parity follow-up. |

PR #25 also notes `fixed`, `any`, and interfaces as scope questions. RTI rejects
the `fixed` and `any` member probes. It warns and ignores an unannotated
interface for C# generation (`C097`); these are not proposed DDS topic-type
follow-ups. The example from issue #24 is already covered by
`C039`, `C022`, `C023`, and `C015`; its combined form needs no separate
follow-up. Optional aggregate support remains distinct under `C115`.
