# Corpus feature coverage

This is the feature index for the managed-generator compatibility corpus. Each case has a stable `C###` tag that can be used in test names, issues, and implementation work. Tags normally follow manifest order; explicit manifest tags preserve existing references when classified cases are added to an earlier group. Case rows are ordered by IDL filename for browsing.

Union and other generated API behavior is covered by the [runtime contract suite](../../tests/Wireloom.Dds.Generator.RuntimeContracts/README.md#coverage-matrix). The corpus table below tracks source acceptance and generated-shape compatibility.

## Status meanings

- `implemented`: the managed generator compiles the IDL and the generated public data-contract shape contains the required RTI oracle types, properties, and enum members.
- `partial`: the managed generator compiles the IDL, but the public shape still differs from the oracle.
- `unsupported`: the RTI-positive case is currently rejected by the managed generator.
- `rejected`: a negative probe is rejected as expected by the managed generator.
- `mismatch`: a negative probe is accepted unexpectedly.
- `isolated`: the probe is present but must be run in an isolated process because the current compiler overflows in-process.
- `accepted`: the managed generator accepts the case, but no generated evidence is committed.
- `pending`: the case is reserved for an RTI probe; managed output is generated, but no RTI oracle is claimed yet.
- `environment-dependent`: observed RTI results differ across RTI/preprocessor environments; see the case diagnostics in the manifest.

RTI oracle links point to the licensee-generated C# source under `corpus/oracles`. Rejected RTI cases have no generated C# source. The `RTI C# compile` column records whether the retained source/plugin pair compiles against the repository's RTI dependency.

- The inventory tests verify that all IDLs and oracle case directories remain aligned.
