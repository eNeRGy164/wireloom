# RTI 7.3.1 feature coverage

This is the retained RTI Connext DDS 7.3.1 / `rtiddsgen` 4.3.1 evidence set.
Its version-specific oracle sources and Wireloom exports are in
[`rtiddsgen/csharp/`](rtiddsgen/csharp/), [`rtiddsgen/cpp/`](rtiddsgen/cpp/),
and [`generator/`](generator/). The shared case IDs, feature links, and
Wireloom acceptance status remain in the [root feature index](../FEATURE-COVERAGE.md).

The 7.3.1 profile is selected automatically for resolved RTI versions from
7.3.1 up to, but not including, 7.7.0. Only exact 7.3.1 has qualification
evidence. The retained run generated RTI C# output for 75 of 77 positive
cases; `07-union-wchar-label` and `09-autoid-hash` were rejected. The RTI
C# compile status was not captured systematically. See the
[RTI generation comparison](RTI-GENERATION-COMPARISON.md) and per-case
[`rtiddsgen-status.tsv`](rtiddsgen-status.tsv).

Wireloom's 7.3.1 profile rejects `09-autoid-hash` with `DDSG0004` because
`@must_understand` is unavailable in that API profile. This target-compatibility
result is distinct from RTI's own `rtiddsgen` rejection. The generated Wireloom
contracts compile against the exact 7.3.1 NuGet package, and all 527
runtime-contract tests pass on that package. The full local 7.3.1 wire matrix
has now run in four Docker shards with copied source trees. It recorded 1,233
passing and 144 failing exchanges out of 1,377; the `09-autoid-hash` negative
case was excluded from the matrix because Wireloom correctly rejects it for
this profile. The complete report and scenario-level results are in the
[7.3.1 combined wire report](../../../artifacts/local-wire-compatibility-rti-7.3.1/combined/results.md).

The matrix confirms that `05-unbounded-sequence-aliases` compiles and passes
Wireloom C# self-exchanges and Wireloom C# / RTI C++ exchanges after correcting
the shared fixture to insert the `int` element required by the generated
`ISequence<int>`. Exchanges involving RTI C# still fail in its
`FromDynamicData` implementation. Several other failures have separate causes:
the signed `int8` boundary fixtures throw `OverflowException` in the harness
before publication, and union interoperability failures are detailed by case
in the report. These results are 7.3.1 evidence only; they do not change the
7.7.0 feature status or qualify every 7.3.1 feature.

## Detailed 7.3.1 feature comparison

The linked case details below retain the original IDL, RTI C# oracle, Wireloom
C# output, and relevant runtime or wire notes. RTI C++ generation outcomes and
source lists are recorded in the [C++ oracle manifest](rtiddsgen/cpp/manifest.json).
Wire notes that cite the 7.7.0 main-branch run are historical context and do
not represent 7.3.1 matrix results.

## Reading the comparisons

- **RTI C# result / compile** reports whether RTI accepted the IDL and whether
  the retained C# source/plugin pair compiles. `not verified` means the
  compilation result is not recorded; it does not mean generation failed.
- `accepted` means RTI generated C# for the IDL; it does not assert that no
  warnings were emitted. `accepted (warning)` records successful generation
  with a warning, while `warning/ignored` records a warning that a construct
  was ignored. `rejected` means RTI did not generate C# for the case.
- **RTI C# oracle folder** links to the retained RTI C# oracle directory when
  RTI generated one.
- **Wireloom C# shape vs RTI C#** states the Wireloom comparison. “Required RTI
  C# shape checks pass” means the generated output contains the required oracle
  types, properties and their types, and enum members checked by the corpus
  suite. It does not establish identical public APIs: constructors, overloads,
  additional members, attributes, and runtime or DDS wire behavior are outside
  this check. Intentional differences are stated on their rows. If RTI rejected
  the input, a shape comparison is unavailable.
- **Wireloom C# generated output** links to the generated files for that case.
- **Runtime / DDS wire notes** records known constraints, reference-peer
  findings, and tracked interoperability gaps. A cited 7.7.0 result is not a
  7.3.1 test result.
  `—` means no additional note is recorded here; it does not mean the case was
  untested, passed, or failed. Use the named report below for execution outcomes.
- `🚩` marks a tracked compatibility or interoperability gap and links to its
  GitHub issue.

Negative probes are grouped by why they were collected. That grouping does not
imply Wireloom should reject every probe: both generator results are stated
independently on the row.

## Adoption summary

The corpus covers a representative generator feature envelope. Passing a
corpus case establishes the documented generation or shape result for that
case; it does not by itself establish runtime or DDS wire compatibility.

- **Primitives and aliases:** primitive values and boundary cases, enums,
  constants, scoped declarations, and aggregate or scalar typedef chains are
  represented. The RTI C# oracle comparisons describe generated API shape.
- **Collections and aggregates:** bounded and unbounded strings and sequences,
  arrays, nested collection compositions, structs, inheritance, recursion,
  and valuetypes are represented. C018 arrays of direct sequence members have
  an unsupported mapping; use a sequence typedef before declaring the array.
- **Unions:** primitive and enum discriminators, default branches, aliases,
  multi-label branches, and collection branches are represented. C137 has a
  default-branch cross-language mismatch; C141 has unresolved RTI C++
  interoperability, while RTI C# also fails compilation for both numeric
  `char` label cases.
- **Annotations and evolution:** topic/key/default annotations, member IDs,
  optional members, extensibility, and data-representation annotations are
  represented. C047 records that `FLAT_DATA` is ignored for C#; its
  FlatData-specific C++ layout is outside this matrix. C064 is an
  accepted/ignored tolerance probe.
- **Preprocessing:** include resolution, command-line defines, conditional
  branches, macros, macro operators, and platform-specific preprocessor probes
  are represented.
- **Restrictions and workarounds:** the negative probes record rejected syntax
  and unsupported constructs. Consult each row for the responsible tool and
  outcome; the detailed index is not a claim that every rejected construct is
  unique to Wireloom.

## Runtime evidence baseline

The full wire matrix has not been run for RTI 7.3.1. The retained exact-version
C130 focused run passed all 27 exchanges using the shared IDL and no
case-specific C++ adaptation. This single-case result does not qualify the
complete 7.3.1 profile. Runtime-contract evidence is summarized above and
detailed in the [runtime contract matrix](../../../tests/Wireloom.Dds.Generator.RuntimeContracts/README.md#coverage-matrix).

The known notes in individual rows link to shared defect reports and prior
profile-specific findings where available; they are not evidence that the full
7.3.1 wire matrix passed or failed. For reproducible 7.3.1 runtime evidence,
use the [wire-matrix guide](../../../tests/Wireloom.Dds.Generator.WireCompatibility/README.md)
and record the tested revision, fixtures, pairings, and adaptations.

- Inventory tests check that IDLs and oracle case directories remain aligned.
