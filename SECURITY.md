# Security Policy

## Reporting a vulnerability

Report security vulnerabilities in Wireloom's source code, published packages,
or build integration through [GitHub private vulnerability reporting](https://github.com/eNeRGy164/wireloom/security/advisories/new).
Do not include vulnerability details in a public issue, discussion, or pull
request. If private reporting is unavailable, [open an issue](https://github.com/eNeRGy164/wireloom/issues)
without sensitive details and ask for a private reporting channel.

A vulnerability is a weakness that could affect the confidentiality, integrity,
or availability of Wireloom or users' builds. Reports are most useful when they
include the affected version or commit, the impact, steps to reproduce, and any
known mitigations. Please avoid accessing or changing data that is not yours,
and avoid disrupting services or other users while investigating.

For problems in RTI Connext DDS or another dependency that are not caused by
Wireloom, report the issue to that project's maintainers. You may also report
any effect on Wireloom through the private channel above.

## Response and disclosure

Maintainers aim to acknowledge vulnerability reports within 7 calendar days.
We will assess the report and coordinate a fix and public disclosure with the
reporter. Our target is to disclose within 90 days of receiving a report when
feasible; the reporter and maintainers may agree to a different timeline based
on severity, remediation, and user risk. Please keep vulnerability details
private until the coordinated disclosure date.

For ordinary bugs and support requests, use the [public issue tracker](https://github.com/eNeRGy164/wireloom/issues).
